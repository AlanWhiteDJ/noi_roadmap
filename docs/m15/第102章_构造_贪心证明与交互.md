# 第 102 章  构造、贪心证明与交互

## 📖 故事引入

模拟赛第三题只有一句话：

> 给定 n，构造一个 1..n 的排列，使得任意两个相邻数的差的绝对值互不相同。

你盯着屏幕十分钟，脑子里全是"这也能出题？"

同桌已经在本子上写开了：

```
n=3: 1 3 2     差 2 1
n=4: 1 4 2 3   差 3 2 1
n=5: 1 5 2 4 3 差 4 3 2 1
```

"你看，"他说，"把最小的放开头，最大的放第二个，再放第二小、第二大……一高一低地走。"

"为什么一定合法？"

"因为差会从 n−1 一路降到 1，正好 n−1 个，一个不多一个不少。"

你突然明白：构造题的答案往往只有五行，难的是**先手算三个小例子**，然后说清"为什么它一定对"。

这一章就讲三件事：怎么想出构造、怎么证明贪心、怎么在交互题里不被判超限。

## 🧱 知识讲解

### 102.1  构造：先做小，再扩

不要一上来写通用解。按这个顺序走：

1. 手算 n = 1、2、3、4，把答案列成表
2. 找规律：是奇偶分讨？对称？还是"一半升一半降"？
3. 想增量：已知 n−1 的解，怎么加一个元素而**不破坏已有性质**
4. 用小数据验证，再写代码

第 3 步是核心。增量构造的关键不是"能加进去"，而是"加了之后原来的性质还成立"。

```cpp
// 1..n 的排列，使相邻差的绝对值互不相同
vector<int> a;
for (int i = 1, j = n; i <= j; ) {
    a.push_back(i++);              // 放当前最小
    if (i <= j) a.push_back(j--);  // 再放当前最大
}
```

n = 5 时得到 `1 5 2 4 3`，差是 `4 3 2 1`；n = 6 时得到 `1 6 2 5 3 4`，差是 `5 4 3 2 1`。

### 102.2  交换论证：排序类贪心的标准证明

套路只有一句话：**假设最优解里有一对相邻元素顺序不对，交换它们，证明答案不变差；反复交换直到有序，说明排序解不劣于最优解。**

以"国王游戏"为例。国王和 n 个大臣站成一排，每人左右手各一个整数。大臣的金币数 = 排在他前面的所有人左手数之积 ÷ 他自己右手数（向下取整）。国王想让金币最多的人拿得尽量少。

考虑相邻的两个人 i、j，设他们前面所有人的左手乘积是 S。

| 顺序 | i 的收益 | j 的收益 |
|------|---------|---------|
| i 在前 | S / bᵢ | S·aᵢ / bⱼ |
| j 在前 | S / bⱼ | S·aⱼ / bᵢ |

记 `A = S/bᵢ`、`B = S/bⱼ`、`X = S·aᵢ/bⱼ`、`Y = S·aⱼ/bᵢ`。由 `aᵢ, aⱼ ≥ 1` 得 `A ≤ Y`、`B ≤ X`：

- 若 `X ≤ Y`，i 在前的最大值不超过 Y，而 j 在前的最大值至少是 Y，i 在前不劣
- 若 `X > Y`，同理 j 在前更优

所以谁在前，只看 X 与 Y：

```
i 在前更优  ⟺  S·aᵢ/bⱼ ≤ S·aⱼ/bᵢ
            ⟺  aᵢ·bᵢ ≤ aⱼ·bⱼ
```

于是排序关键字就是 `a*b`：

```cpp
sort(p + 1, p + n + 1, [](const P &x, const P &y) {
    return 1LL * x.a * x.b < 1LL * y.a * y.b;
});
```

两个细节：

- **用乘法比较，不要算除法**，避免浮点误差
- `a*b` 到 10⁸，比较时用 `long long`；但**答案**是前缀积除以右手数，n = 1000、a = 10⁴ 时前缀积有四千多位，必须高精度

### 102.3  下界 + 构造：自己证明自己

构造题最怕"看起来对"。可靠的自证方式是两条腿：

1. **下界**：证明任何合法方案都不可能比 X 更好
2. **构造**：给出一个正好达到 X 的方案

两者一夹，正确性就成立了。

回到开头的排列题：

- 相邻差一共有 n−1 个，每个差的取值只能是 1..n−1，一共也只有 n−1 种
- 要求"互不相同"，就必须**恰好用遍** 1..n−1
- 一高一低的走法，差正好是 n−1, n−2, …, 1，取满且不重复

下界和构造同时成立，这题就结束了。比"我试了 n ≤ 10 都对"强得多。

### 102.4  交互题：协议比算法更重要

交互题的输入是"对话"：你输出一次询问，评测机回答一次。

三条铁律：

1. **每次输出后必须 flush**，否则对方收不到
2. 询问次数有上限，先算清每次能排除多少
3. 最后要按题目规定的格式输出答案（通常是 `! ans` 或直接输出）

```cpp
cout << "? " << mid << endl;   // endl 自带 flush
int r; cin >> r;
...
cout << "! " << ans << endl;
```

用 `'\n'` 而不 flush，本地可能正常，交上去就是 TLE 或 WA——这是交互题第一大坑。若坚持用 `'\n'`，要显式 `cout.flush();`。

猜数（1..n，每次问"大了还是小了"）是标准二分，询问次数 `⌈log₂ n⌉`：

```cpp
int lo = 1, hi = n;
while (lo < hi) {
    int mid = (lo + hi) >> 1;
    cout << "? " << mid << endl;
    int r; cin >> r;               // 1 表示 mid 大了，0 表示小了
    if (r == 1) hi = mid;
    else lo = mid + 1;
}
cout << "! " << lo << endl;
```

n = 1000 时 10 次就够，因为 `2¹⁰ = 1024 > 1000`。写之前先算这个数，才不会因为多问一次而超限。

### 102.5  贪心不成立的信号

三种情况要立刻警惕：

- 交换两个元素后，**别的元素收益也跟着变**（有后效性）→ 贪心可能不成立
- 局部最优的选择会**堵死**后面的更优选择 → 想想反例
- 题目要求"最大值最小 / 最小值最大" → 多半是二分答案，不是纯贪心

拿不准时，写个 O(2ⁿ) 暴力对拍 n ≤ 10，比空想快得多。

## 💻 例题

### 例 1  构造相邻差互不相同的排列

n = 5，输出任意合法排列。

**解析**：按 102.1 的代码，得到 `1 5 2 4 3`。

验证：

| 相邻对 | (1,5) | (5,2) | (2,4) | (4,3) |
|--------|-------|-------|-------|-------|
| 差的绝对值 | 4 | 3 | 2 | 1 |

四个差正好是 1..4，互不相同。n = 1 时特判：直接输出 `1`（没有相邻对，"互不相同"平凡成立）。写构造题一定要想 n = 1。

### 例 2  国王游戏

输入（第一行 n，接着 n+1 行：国王在前，随后 n 个大臣，每行左右手数）：

```
2
2 1
1 1
3 5
```

输出：`2`。

**解析**：国王左手为 2。两个大臣按 `a*b` 排序：`1*1 = 1 < 3*5 = 15`，顺序就是 (1,1)、(3,5)。

- 第 1 个大臣：前面乘积 2，金币 `2/1 = 2`
- 第 2 个大臣：前面乘积 `2*1 = 2`，金币 `2/5 = 0`

最大值 2，与输出一致。

如果反过来排：第 1 个 `2/5 = 0`，第 2 个 `2*3/1 = 6`，最大值变成 6——交换论证说的就是这件事：`a*b` 小的在前，最大值不会变大。

高精度的核心是两个函数：

```cpp
struct Big {
    vector<int> a;                       // 低位在前
    Big(long long x = 0) {
        if (!x) a.push_back(0);
        while (x) { a.push_back(int(x % 10)); x /= 10; }
    }
    void trim() { while (a.size() > 1 && !a.back()) a.pop_back(); }
};

Big bigMul(const Big &A, int b) {           // 高精度 × 低精度
    Big C; C.a.assign(A.a.size() + 1, 0);
    for (size_t i = 0; i < A.a.size(); i++) C.a[i] += A.a[i] * b;
    for (size_t i = 0; i + 1 < C.a.size(); i++) {
        C.a[i + 1] += C.a[i] / 10;
        C.a[i] %= 10;
    }
    C.trim(); return C;
}

Big bigDiv(const Big &A, int b) {           // 高精度 ÷ 低精度
    Big C; C.a.assign(A.a.size(), 0);
    long long r = 0;
    for (int i = (int)A.a.size() - 1; i >= 0; i--) {
        r = r * 10 + A.a[i];
        C.a[i] = int(r / b);
        r %= b;
    }
    C.trim(); return C;
}
```

再写一个比较函数，边乘边更新最大值即可。

### 例 3  交互猜数

n = 1000，猜中即结束。

**解析**：二分。第 1 次问 500，剩 500 个可能；第 2 次剩 250……第 10 次剩不到 1 个。询问次数 `⌈log₂ 1000⌉ = 10`。

如果题目限制"最多 9 次"，二分就必然失败——这时要先算 `2⁹ = 512 < 1000`，说明信息量不够，得换题设允许的其他手段（比如利用返回值的三态）。**先算次数，再写代码**，这是交互题的唯一正确顺序。

## ⚠️ 你踩过这些坑吗

- [ ] **坑 1：贪心只写结论不写证明** — 数据一改就挂，而且你不知道挂在哪。
- [ ] **坑 2：交互题用 `'\n'` 不 flush** — 本地能过，评测 TLE/WA。
- [ ] **坑 3：询问次数算错** — 多问一次就超限，写之前先算 `log₂`。
- [ ] **坑 4：构造题忘了 n = 1、n = 2** — 边界往往不满足一般规律。
- [ ] **坑 5：比较用除法** — 浮点误差让排序不稳定，用交叉相乘。

## 🧠 本章小结

```
构造：手算 n=1,2,3 → 找规律 → 增量加元素不破坏性质 → 验边界

交换论证：相邻两人顺序互换，证明不劣 → 得到排序关键字

      猜数 = 二分，⌈log₂ n⌉ 次
```
