# 第 102 章  构造、贪心证明与交互
> 🏗️ **前情回顾**：上册第 48 章你学过"排序后取最优"的贪心。考场上真正难的不是想到贪心，而是**证明它**；也不是写出算法，而是**构造一组合法解**。
## 🎯 本章目标
- 用"从特殊到一般"和增量构造写出合法方案
- 用交换论证证明排序类贪心
- 读懂交互题协议，控制询问次数
- 知道贪心如何自证：下界 + 构造
## 🧱 知识讲解
### 102.1  构造：先做小，再扩
不要一上来写通用解。先手算 n=1,2,3 找模式，再想"已知 n-1 的解，怎么加一个元素"。增量构造的关键是**不破坏已有性质**。
```cpp
// 1..n 的排列，使相邻差的绝对值互不相同
vector<int> a;
for (int i = 1, j = n; i <= j; ) {
    a.push_back(i++);
    if (i <= j) a.push_back(j--);
}
```
### 102.2  交换论证
假设最优解里有一对相邻元素顺序反了，交换它们并证明答案不变差；反复交换直到有序，说明排序解不劣于最优。国王游戏中，前者在前更优等价于 `a1*b1 < a2*b2`：
```cpp
sort(p + 1, p + n + 1, [](P x, P y) { return x.a * x.b < y.a * y.b; });
```
比较用乘法不用除法，避免精度；乘积到 10^8 用 `long long`，答案要高精度。
### 102.3  交互题协议
每次输出必须换行并 flush，否则对方收不到；询问次数有上限，先算清每次能排除多少：
```cpp
cout << "? " << l << ' ' << r << endl;   // endl 自带 flush
int res; cin >> res;
cout << "! " << ans << endl;             // 最后给出答案
```
### 102.4  构造题的自证
两条腿：给出一个**下界**（任何方案都不可能更好），再给出**达到下界的构造**。两者一夹，正确性就成立，比"看起来对"可靠得多。
## 💻 例题
**例 1（P1080 国王游戏）**：交换论证得排序关键字 `a*b`，再高精度算前缀积除以各人右手数，取最大值。
**例 2（CSP-S 2021 回文）**：2n 个数从两端取，填成回文且操作序列字典序最小。枚举第一步取左或取右，之后双指针强制配对，两方案取字典序小者。
## ⚠️ 常见坑
1. 贪心只写结论不写证明，数据一改就挂
2. 交互题用 `'\n'` 不 flush，直接 TLE/WA
3. 二分边界写错，多问一次导致超限
4. 构造题没验 `n=1`、`n=2` 的边界
