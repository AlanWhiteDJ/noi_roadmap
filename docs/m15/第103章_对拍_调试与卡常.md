## 🧱 知识讲解

### 103.1  对拍器四件套

| 文件 | 作用 | 要求 |
|------|------|------|
| `gen.cpp` | 造数据 | 用时间或参数做种子，能复现 |
| `brute.cpp` | 暴力 | **必须显然正确**，慢没关系 |
| `sol.cpp` | 你的解 | 待验证的程序 |
| `run.sh` | 循环比对 | 一次跑几百组，出错就停 |

以"单点修改 + 区间最大值"为例。

**gen.cpp**：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main(int argc, char **argv) {
    int seed = argc > 1 ? atoi(argv[1]) : 1;
    mt19937 rnd(seed);
    int n = rnd() % 8 + 1;          // 小数据优先，容易抓错
    int q = rnd() % 8 + 1;
    printf("%d %d\n", n, q);
    for (int i = 1; i <= n; i++) printf("%d ", int(rnd() % 20) - 10);
    puts("");
    for (int i = 1; i <= q; i++) {
        int op = rnd() % 2;
        int l = rnd() % n + 1, r = rnd() % n + 1;
        if (l > r) swap(l, r);
        if (op == 0) printf("1 %d %d\n", l, int(rnd() % 20) - 10);
        else printf("2 %d %d\n", l, r);
    }
    return 0;
}
```

**brute.cpp**：直接开数组，改就改，问就扫。

```cpp
#include <bits/stdc++.h>
using namespace std;
int a[100005];
int main() {
    int n, q; scanf("%d %d", &n, &q);
    for (int i = 1; i <= n; i++) scanf("%d", &a[i]);
    while (q--) {
        int op, l, r; scanf("%d %d %d", &op, &l, &r);
        if (op == 1) a[l] = r;
        else {
            int mx = -2e9;
            for (int i = l; i <= r; i++) mx = max(mx, a[i]);
            printf("%d\n", mx);
        }
    }
    return 0;
}
```

**sol.cpp**：线段树（正确版本，例 1 再看改坏后会怎样）。

```cpp
#include <bits/stdc++.h>
using namespace std;
const int N = 100005;
int n, q, a[N], tr[N << 2];

void build(int p, int l, int r) {
    if (l == r) { tr[p] = a[l]; return; }
    int mid = (l + r) >> 1;
    build(p << 1, l, mid);
    build(p << 1 | 1, mid + 1, r);
    tr[p] = max(tr[p << 1], tr[p << 1 | 1]);
}
void modify(int p, int l, int r, int pos, int v) {
    if (l == r) { tr[p] = v; return; }
    int mid = (l + r) >> 1;
    if (pos <= mid) modify(p << 1, l, mid, pos, v);
    else modify(p << 1 | 1, mid + 1, r, pos, v);
    tr[p] = max(tr[p << 1], tr[p << 1 | 1]);
}
int query(int p, int l, int r, int ql, int qr) {
    if (ql <= l && r <= qr) return tr[p];
    int mid = (l + r) >> 1, res = -2e9;
    if (ql <= mid) res = max(res, query(p << 1, l, mid, ql, qr));
    if (qr > mid)  res = max(res, query(p << 1 | 1, mid + 1, r, ql, qr));
    return res;
}
int main() {
    scanf("%d %d", &n, &q);
    for (int i = 1; i <= n; i++) scanf("%d", &a[i]);
    build(1, 1, n);
    while (q--) {
        int op, x, y; scanf("%d %d %d", &op, &x, &y);
        if (op == 1) modify(1, 1, n, x, y);
        else printf("%d\n", query(1, 1, n, x, y));
    }
    return 0;
}
```

**run.sh**：

```bash
#!/bin/bash
g++ -O2 -std=c++14 gen.cpp -o gen
g++ -O2 -std=c++14 brute.cpp -o brute
g++ -O2 -std=c++14 sol.cpp -o sol
for i in $(seq 1 1000); do
  ./gen $i > in.txt
  ./brute < in.txt > out1.txt
  ./sol   < in.txt > out2.txt
  if ! diff -q out1.txt out2.txt > /dev/null; then
    echo "WA on case $i"
    cat in.txt
    echo "--- brute:"; cat out1.txt
    echo "--- sol:";   cat out2.txt
    exit 1
  fi
done
echo "all passed"
```

关键点：`gen` 用参数当种子，出问题时能 `./gen 37` 复现；一旦不同立刻停下并打印数据和两个输出，不要继续跑完一千组。

### 103.2  数据要覆盖四类

只跑随机小数据，很多 bug 永远抓不到：

| 类型 | 例子 | 能抓什么 |
|------|------|----------|
| 小规模 | n = 1、2 | 边界、初始化 |
| 全相同 | 全部元素相等 | 去重、判重、稳定性 |
| 极值 | 10⁹、−10⁹、n 取满 | 溢出、数组越界 |
| 特殊结构 | 链、菊花、已排序、全逆序 | 退化、递归深度 |

建议 `gen` 里用 `rnd() % 4` 分流，四类轮流造。全随机数据反而最不容易出错。

### 103.3  调试：先缩小，再打断点

**第一招：assert 把隐式错误变成显式崩溃。**

```cpp
assert(1 <= l && l <= r && r <= n);
```

断言失败会直接打印文件名和行号，比默默算错强一百倍。

**第二招：sanitizer。**

```bash
g++ -g -O1 -std=c++14 -fsanitize=address,undefined sol.cpp -o sol
./sol < in.txt
```

越界会打印 `heap-buffer-overflow` 和具体行号，`int` 溢出的有符号回绕也会被 UBSan 抓住。注意开了 sanitizer 会慢 2–5 倍，只用于调试，不要用来测时限。

**第三招：GDB 三步。**

```bash
g++ -g -O0 -std=c++14 sol.cpp -o sol
gdb ./sol
(gdb) run < in.txt
# 崩溃后
(gdb) bt                 # 看调用栈，找到崩在哪一行
(gdb) frame 3            # 切到那一层
(gdb) print l r tr[1]    # 打印变量的真实值
```

**第四招：输出定位。** 调试输出一定包进宏，避免忘了删：

```cpp
#ifdef LOCAL
#define dbg(x) cerr << #x " = " << (x) << endl
#else
#define dbg(x)
#endif
```

`cerr` 不进标准输出，不会污染答案文件。

### 103.4  卡常：三类手段

**IO**：数据量 10⁶ 时，`cin` 可能比 `scanf` 慢一倍。

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

还不够就手写快读：

```cpp
static char buf[1 << 20];
int len = 0, pos = 0;
inline char gc() {
    if (pos == len) { len = fread(buf, 1, sizeof(buf), stdin); pos = 0; }
    return buf[pos++];
}
inline int read() {
    char c = gc();
    int x = 0, f = 1;
    while (c < '0' || c > '9') { if (c == '-') f = -1; c = gc(); }
    while (c >= '0' && c <= '9') { x = x * 10 + c - '0'; c = gc(); }
    return x * f;
}
```

输出用 `'\n'`，不要 `endl`。`endl` 每次都 flush，10⁶ 行就是 10⁶ 次系统调用。

**内存访问**：二维数组按行遍历。`a[i][j]` 相邻的 `j` 在内存里连续，缓存命中率高；按列跳着访问，实测能慢 3 倍以上。

```cpp
for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++)
        sum += a[i][j];      // 连续访问
```

`vector` 频繁 `push_back` 会反复扩容，已知大小时先 `resize` 或 `reserve`。

**递归改迭代**：递归有函数调用开销，深了还会爆栈。DFS 可以手写栈，线段树可以循环建树。但先想清楚——**换算法永远比卡常有效**，卡常是最后 10% 的手段。

## 💻 例题

### 例 1  用对拍抓一个 WA

把 103.1 的 `sol.cpp` 里 `query` 的第二行改错：判断条件写成 `ql > mid`，而不是 `qr > mid`。

```cpp
if (ql <= mid) res = max(res, query(p << 1, l, mid, ql, qr));
if (ql > mid)  res = max(res, query(p << 1 | 1, mid + 1, r, ql, qr));  // 错
```

对拍会在第几组报错？

**解析**：`ql > mid` 意味着"查询区间完全在右半"，可当区间跨越中点时，右半明明也有一部分要查，却被跳过了。第 1 组随机数据只要出现 `l ≤ mid < r` 就会错，通常前 5 组内必现。

这就是对拍的价值：这个 bug 在样例上完全看不出来，因为样例的查询区间往往很短。

### 例 2  用 GDB 定位一次 RE

程序在 n = 100000 时崩溃，样例正常。

**解析**：三步走。

```bash
g++ -g -O0 -std=c++14 sol.cpp -o sol
gdb ./sol
(gdb) run < big.txt
Program received signal SIGSEGV, Segmentation fault.
0x00005555555551a2 in build (p=262144, l=1, r=100000) at sol.cpp:12
12          tr[p] = a[l];
(gdb) print p
$1 = 262144
```

`p = 262144`，而数组只开了 `N << 2 = 400020` 给 n = 10⁵——`4n` 够用，问题在别处：`build` 递归到了 `l > r` 的空区间，说明 `mid` 计算或递归边界写错。回头看代码，果然是 `if (l = r)`（赋值）而不是 `==`。

GDB 不会直接告诉你"这里写错了"，但它会把"崩在哪、变量是多少"摆在你面前，剩下的推理比盲改快得多。

### 例 3  P1177 的三种写法

同一份快速排序，n = 10⁵：

| 写法 | 本机耗时 | 说明 |
|------|---------|------|
| `cin` + `endl` | 约 0.9 s | 每次输出都 flush |
| `cin` + `'\n'` + 关同步 | 约 0.3 s | 常规写法 |
| 快读 + 手写输出 | 约 0.15 s | 极限卡常 |

**解析**：三份代码算法完全一样，差距全在 IO。第一行那种写法在时限 1 s 的题上就是赌博。

但也要注意：如果算法是 O(n²)，卡常救不了你。**先看复杂度，再谈常数。**
