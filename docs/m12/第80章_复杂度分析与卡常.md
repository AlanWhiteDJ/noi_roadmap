## 📖 故事引入

模拟赛第二题，你和同桌都写了归并排序。交卷后他 0.4 秒，你 2.9 秒。你第一反应是评测机在抖，重交三次，还是 2.9 秒。

下课后你把两份代码并排看，发现三处不同：他输出用 `'\n'`，你用了 `endl`；他把二维数组按行遍历，你按列；他在循环外算好了 `strlen`，你在 `for` 的判断条件里每轮都算一次。

算法一模一样，成绩差了七倍。教练只说了一句：**大 O 决定量级，常数决定你能不能活着交上去。**

这一章就解决这件事：先学会算，再学会省。

## 🧱 知识讲解

### 80.1  先算规模，再写代码

评测机大约每秒做 10⁸ 次简单运算（不同机器在 2×10⁸ 到 5×10⁸ 之间浮动）。把 n 代进去，就能反推允许的复杂度：

| n 的上限 | 可接受的复杂度 | 典型算法 |
|----------|----------------|----------|
| 10 | O(n!)、O(nⁿ) | 全排列、暴力枚举 |
| 20 | O(2ⁿ) | 子集枚举、状压 DP |
| 500 | O(n³) | Floyd、区间 DP |
| 5000 | O(n²) | 普通 DP、双重循环 |
| 10⁵ | O(n log n) | 排序、树状数组、堆 |
| 10⁶ | O(n)、O(n log n) 勉强 | 线性扫描、前缀和 |

看题时按顺序问自己三句话：

1. n 有多大？
2. 我的做法是哪个量级？
3. 乘起来有没有超过 10⁸？

比如 n = 10⁵ 时你写了两重循环，就是 10¹⁰ 次运算，约 100 秒——不用交也知道是 TLE，必须换算法。

> 💡 留余量：估算出来接近 10⁸ 就要警惕。常数大的做法（STL、取模、浮点）实际只能承受 10⁷ 左右。

### 80.2  主定理：递归复杂度的快算法

分治代码的复杂度形如

```
T(n) = a·T(n/b) + f(n)
```

其中 a 是子问题个数，b 是规模缩小倍数，f(n) 是划分与合并的代价。令 c = log_b a，比较 f(n) 与 n^c：

- f(n) 比 n^c 小 → T(n) = Θ(n^c)
- 两者同阶 → T(n) = Θ(n^c · log n)
- f(n) 比 n^c 大（且满足正则条件）→ T(n) = Θ(f(n))

三个必须记住的例子：

| 算法 | a | b | f(n) | 结果 |
|------|---|---|------|------|
| 归并排序 | 2 | 2 | O(n) | O(n log n) |
| 二分查找 | 1 | 2 | O(1) | O(log n) |
| 二分答案 + O(n) 判定 | 1 | 2 | O(n) | O(n log n) |

主定理管不了"只递归一边"的情形。快速选择每次只进一半，递推式是 T(n) = T(n/2) + O(n)，展开得 O(n)，这是期望复杂度，不是主定理的直接结论。

### 80.3  把 IO 常数压下去

C++ 的 `cin`/`cout` 默认和 C 的 `stdio` 同步，每次读写都要加锁检查。关掉同步、解开绑定，通常能快 2–3 倍：

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

注意：关同步之后不要再混用 `scanf`/`printf`，也不要再用 `getchar` 读同一份输入。

`endl` 会刷新缓冲区，循环输出十万行时改用 `'\n'`：

```cpp
for (int i = 0; i < n; i++)
    cout << a[i] << '\n';   // 不要用 endl
```

输入量到 10⁶ 以上时，手写快读还能再快一截：

```cpp
inline int read() {
    int x = 0, f = 1;
    char c = getchar();
    while (c < '0' || c > '9') {
        if (c == '-') f = -1;
        c = getchar();
    }
    while (c >= '0' && c <= '9') {
        x = x * 10 + (c - '0');
        c = getchar();
    }
    return x * f;
}
```

快读的坑：文件末尾 `getchar()` 返回 `EOF`，如果输入格式不合法会死循环；负号必须在数字前处理。平时用 `cin` 加前两行优化已经够，快读留给真正卡时间的题。

### 80.4  访问顺序与位运算

CPU 读内存时按缓存行（通常 64 字节）整块搬运。你按行访问，下一格就在缓存里；按列访问，每次都换一条缓存行。

```cpp
// 快：按行连续访问，缓存友好
for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++)
        sum += a[i][j];

// 慢：按列跳着访问，缓存反复失效
for (int j = 0; j < m; j++)
    for (int i = 0; i < n; i++)
        sum += a[i][j];
```

矩阵小的时候差别不明显，n = m = 3000 时按列可能慢三到五倍。

位运算的价值在于"一条指令干几件事"：

```cpp
int c = __builtin_popcount(x);          // 二进制中 1 的个数
int low = x & -x;                       // 最低位的 1
for (int s = x; s; s = (s - 1) & x) {}  // 枚举 x 的非空子集
```

`x & (x - 1)` 每次消掉最低位的 1，循环次数等于 1 的个数；`__builtin_ctz(x)` 给出末尾 0 的个数。这些在状压 DP、线性基、子集枚举里天天用。

不要过度追求"用移位代替乘除 2"——现代编译器本来就会优化，写 `x << 1` 只在语义确实按位时才更清楚。

### 80.5  减少重复计算

常数优化里收益最大的一类，是"把循环里不变的东西搬出去"：

```cpp
// 慢：每轮都调用 strlen，O(n²)
for (int i = 0; i < strlen(s); i++) ...

// 快：长度只算一次
int len = strlen(s);
for (int i = 0; i < len; i++) ...
```

其他常用手法：

- 传参用 `const vector<int>&`，避免整份拷贝
- 预先 `reserve`，减少 `push_back` 的反复扩容
- 用数组代替 `unordered_map`（值域小时）
- 取模次数能合并就合并，`long long` 的 `%` 比加法贵得多
- 递归写成迭代，或至少别用 `std::function` 包 lambda

### 80.6  空间：数组、栈与对齐

256 MB 的内存限制，换算成 `int` 大约是 6.7×10⁷ 个：

```
256 × 1024 × 1024 ÷ 4 ≈ 6.7×10⁷
```

所以 `int a[100000000]` 占 400 MB，直接 MLE；`long long` 还要再翻一倍。

| 类型 | 单字节数 | 10⁷ 个约占 |
|------|----------|------------|
| `char` / `bool` | 1 | 10 MB |
| `int` | 4 | 40 MB |
| `long long` | 8 | 80 MB |
| `double` | 8 | 80 MB |

两个容易忽视的点：

1. **局部大数组会爆栈。** 函数内的 `int a[1000000]` 要 4 MB，而默认栈只有 8 MB（Windows 常见 1 MB），递归再压几层就崩。大数组一律开全局。
2. **结构体有对齐开销。** `struct Node { char c; int x; };` 的 `sizeof` 是 8 而不是 5，10⁷ 个就多花 30 MB。把同类型成员放在一起能省一点。

递归深度到 10⁵ 时，每层哪怕只占几十字节也可能超栈。深搜优先用全局数组存状态，必要时改手动栈或递推。

## 💻 例题

### 例 1  估算这三段代码

n = 10⁵，判断下列代码能否在 1 秒内跑完。

```cpp
// (a)
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (a[i] + a[j] == target) ans++;

// (b)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        for (int k = 0; k < n; k++)
            sum += a[i] * a[j] * a[k];

// (c)
sort(a, a + n);
for (int i = 0; i < n; i++)
    if (binary_search(a, a + n, target - a[i])) ans++;
```

**解析**：

- (a) 循环次数约 n²/2 = 5×10⁹，约 50 秒，超时。改成排序 + 双指针或哈希表，降到 O(n log n)。
- (b) n³ = 10¹⁵，根本跑不完，必须换做法（多半要用前缀和或数学化简）。
- (c) 排序 1.7×10⁶ 次比较，加 n 次二分约 1.7×10⁶ 次，合计 3.4×10⁶，轻松通过。

估算时只看最高阶项，常数留 2–5 倍余量即可。

### 例 2  [P1177](https://hydro.ac/p/luogu-P1177) 排序

n ≤ 10⁵，要求 O(n log n)。直接用 `sort` 最稳：

```cpp
#include <bits/stdc++.h>
using namespace std;
int a[100005];
int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    for (int i = 0; i < n; i++) cin >> a[i];
    sort(a, a + n);
    for (int i = 0; i < n; i++) cout << a[i] << ' ';
    return 0;
}
```

要手写时，用三路快排应对大量重复元素：

```cpp
void quickSort(int l, int r) {
    if (l >= r) return;
    int x = a[l + rand() % (r - l + 1)];
    int i = l, lt = l, gt = r;
    while (i <= gt) {
        if (a[i] < x) swap(a[i++], a[lt++]);
        else if (a[i] > x) swap(a[i], a[gt--]);
        else i++;
    }
    quickSort(l, lt - 1);
    quickSort(gt + 1, r);
}
```

**解析**：`sort` 是内省排序，平均 O(n log n)，最坏也保持 O(n log n)。三路快排把等于基准的元素一次归位，全是相同数时只递归一层；如果固定取首元素做基准，遇到有序数据会退化成 O(n²)。

### 例 3  [P1923](https://hydro.ac/p/luogu-P1923) 求第 k 小

n 可达 5×10⁶，整体排序 O(n log n) 约 1.1×10⁸ 次比较，卡在时限边缘。用 `nth_element`：

```cpp
#include <bits/stdc++.h>
using namespace std;
int a[5000005];
int main() {
    int n, k;
    scanf("%d%d", &n, &k);
    for (int i = 0; i < n; i++) scanf("%d", &a[i]);
    nth_element(a, a + k, a + n);   // k 从 0 开始
    printf("%d\n", a[k]);
    return 0;
}
```

**解析**：`nth_element` 只保证第 k 位就位，左边都不大于它、右边都不小于它，内部用快速选择，平均 O(n)。本题 k 从 0 开始编号；如果题目从 1 开始，就写 `a + k - 1`。n 到 5×10⁶ 时输入量很大，`scanf` 或快读比默认 `cin` 稳。

## ⚠️ 你踩过这些坑吗

- [ ] **坑 1：只看大 O 不看常数** — 同样是 O(n log n)，`endl`、按列访问、STL 过度封装能慢 3 倍以上。
- [ ] **坑 2：循环里重复计算** — `for (int i = 0; i < s.size(); i++)` 每轮都调一次 `size()`，虽然通常会被内联，但 `strlen`、`sqrt` 这类就不会。
- [ ] **坑 3：大数组开在函数内** — 局部数组在栈上，几百 KB 就可能爆栈，表现为"运行错误"而不是 TLE。
- [ ] **坑 4：忘了多测清空** — 多组数据时数组、计数器没重置，第二组开始答案就错，复杂度还会翻倍。
- [ ] **坑 5：以为 10⁸ 一定安全** — 取模、浮点、随机访问内存都会让常数变大，实际按 10⁷ 估更稳。

## 🧠 本章小结

```
先估算，再动手：
  1 秒 ≈ 10⁸ 次简单运算
  n≤20 → 2ⁿ    n≤5000 → n²    n≤10⁵ → n log n

主定理：T(n)=aT(n/b)+f(n)，比较 f(n) 与 n^(log_b a)

常数优化三板斧：
  IO     sync_with_stdio(false) + '\n'，必要时快读
  访问   按行连续，缓存友好
  位运算 popcount / lowbit / (s-1)&x 枚举子集

空间：
  256MB ≈ 6.7×10⁷ 个 int
  大数组开全局，递归别太深
```
