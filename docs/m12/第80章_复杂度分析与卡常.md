## 🎯 本章目标

## 🧱 知识讲解
### 80.1  先算规模，再写代码
评测机约每秒 10⁸ 次简单运算。看到 n 就能反推允许的复杂度：n≤10⁶ 只能 O(n)；n≤10⁵ 可 O(n log n)；n≤5000 考虑 O(n²)；n≤20 才敢用 O(2ⁿ)。主定理 T(n)=aT(n/b)+f(n)：比较 f(n) 与 n^(log_b a)，归并排序 a=b=2、f(n)=O(n)，得 O(n log n)。

### 80.2  把 IO 常数压下去

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

`endl` 会刷新缓冲区，循环输出十万行时改用 `'\n'`；输入更大时手写 `getchar` 快读，输出用 `putchar` 快写。

### 80.3  访问顺序与位运算

```cpp
for (int i = 0; i < n; i++)            // 按行连续访问，缓存友好
    for (int j = 0; j < m; j++) sum += a[i][j];
int c = __builtin_popcount(x);         // 数二进制中 1 的个数
for (int s = x; s; s = (s - 1) & x) {} // 枚举 x 的非空子集
```

二维数组按行遍历常比按列快数倍；`x & (x-1)` 每次消掉最低位的 1，是 lowbit 和子集枚举的基础。

### 80.4  空间：数组、栈与对齐
全局数组在静态区，`int a[100000000]` 就是 400MB，直接 MLE；局部大数组会爆栈。递归深度到 10⁵ 时每层几十字节也可能超栈，深搜优先用全局数组，或改手动栈/递推。

## 💻 例题
**例 1**：[P1177](https://hydro.ac/p/luogu-P1177) 排序。n≤10⁵，`sort` 足够；手写时用三路快排处理大量重复元素，避免退化成 O(n²)。

**例 2**：[P1923](https://hydro.ac/p/luogu-P1923) 求第 k 小。`nth_element(a, a + k, a + n)` 平均 O(n)，只排需要的部分，比整体排序少一个 log。

## ⚠️ 常见坑
1. 只看大 O 不看常数：同样的 O(n log n)，`endl` 和 STL 过度封装能慢 3 倍
2. 递归层数过深导致栈溢出；大数组开在函数内
